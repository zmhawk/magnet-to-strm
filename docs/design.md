# 行为与数据模型

## STRM 规则

仅为视频文件生成 STRM；字幕、图片、文本等非视频文件仍保存到 SQLite。默认路径为 `<磁链名称>/<相对文件路径>.strm`，保留磁链内目录结构；顶层目录冲突时追加 info hash 短后缀。

STRM 使用同目录临时文件和 rename 原子写入。只有真实文件成功写入后，才记录 `strm_seeded_at` 并完成 ingest job。用户移动或删除已生成文件后，重新扫描磁链不会自动恢复。

`info_hash` 只标注首选恢复来源，不参与 SHA1 内容身份、物化缓存键或稳定 DAV 对象路径。

## 重定向流程

1. 优先验证数据库记录的 115 位置。
2. 不存在时按文件名搜索，并以 SHA1 确认内容；搜索所得位置标记为外部位置。
3. 仍不存在时，按来源提示及最近成功顺序创建或恢复 115 离线任务。
4. 任务完成后确认结果包含目标 SHA1；不包含时将旧任务视为失效并重建。
5. `direct` 模式返回当前 115 文件路径；`stable_dav` 模式返回稳定 SHA1 对象路径。

记录内容最后访问时间。每个“内容文件 + 来源磁链”只保留最后一次扫描到的 115 位置。完整扫描结果及 `file_id`、`delete_file_id`、`wp_path_id` 等元数据入库后，删除已完成的离线任务记录，但保留结果文件。

## 稳定 WebDAV

DAV 的两级目录由 SHA1 派生，`PROPFIND` 从 `content_objects` 查询分桶和对象属性，不额外模拟虚拟目录记录。`GET` 和 `HEAD` 通过 SHA1 物化器取得当前 `pick_code`，使用请求的 User-Agent 获取 115 临时下载地址并流式代理；临时地址返回 401、403 或 410 时刷新一次。写操作不透传。

对象 ETag 固定为 SHA1，创建时间使用内容首次入库时间，避免远端路径变化使缓存失效。物化结果按 SHA1 保存在进程内，以最后访问时间滑动过期；`/redirect` 与 `/dav` 共享同一份缓存。115 临时下载地址按 `pick_code + User-Agent` 缓存在进程内，不主动过期；只有下载返回 401、403 或 410 时才精确淘汰旧地址、重新获取并重试一次，相同地址的并发首次获取会合并。

## 数据模型

- `torrents`：磁链、扫描摘要和稳定的 `strm_root`。
- `ingest_jobs`：持久化任务队列。
- `content_objects`：按小写 SHA1 唯一标识的内容。
- `torrent_files`：磁链内相对路径、内容关联及 `strm_seeded_at`。
- `remote_locations`：115 文件位置、`pick_code` 及所有权。
- `credentials`：115 OAuth 凭证。
- `leases`：TOKEN 刷新租约。
